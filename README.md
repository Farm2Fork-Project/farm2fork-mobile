## Running against the backend

```bash
# Android emulator, backend from farm2fork-backend/docker-compose.local.yml
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:3002/api \
            --dart-define=PAYMENT_SIMULATOR_ENABLED=true
# In-memory data, no backend:
flutter run --dart-define=USE_MOCKS=true
```

See `farm2fork-backend/docs/TESTING.md` for the whole-flow test script.

## Google Maps key

Farm pins, the checkout drop-off pin and the transporter maps use the Maps SDK
for Android/iOS. The key is never committed:

1. In Google Cloud, enable **Maps SDK for Android** (and **Maps SDK for iOS**
   for iOS builds) and create an API key restricted to the app's package name
   `com.farm2fork.app` and your signing certificate's SHA-1.
2. Android: add `MAPS_API_KEY=your-key` to `android/local.properties`
   (git-ignored), or export `MAPS_API_KEY` in CI.
3. iOS: create `ios/Flutter/Secrets.xcconfig` (git-ignored) containing
   `MAPS_API_KEY=your-key`.

Release builds refuse to build without `MAPS_API_KEY` (the 14 Oct MVP APK
shipped blank maps); set `ALLOW_MISSING_MAPS_KEY=true` only to build one
deliberately. In a debug build without a key, map views show a fallback card
with an "Open in Google Maps" link instead of a blank (Android) or crashing
(iOS) map. Turn-by-turn navigation opens the Google Maps app, which needs no key.

Transporters share their foreground location while online **or** while a
delivery is active; the farmer (before pickup) and buyer (after pickup) see it
on the shipment's live map, refreshed every 30 seconds while the screen is open.

## Location and notifications

- Location is **foreground only**: transporters share it while they are
  online with the app open, farmers and buyers use it to pin a spot. No
  background location permission is requested.
- Push notifications use Firebase Cloud Messaging. Android 13+ asks for the
  notification permission after sign-in; the device token is registered with
  the backend and cleared on sign-out.

## Distribution release preflight and build

Run `python3 scripts/build_release.py android` for an Android App Bundle, or
`python3 scripts/build_release.py ios` for an iOS IPA. Add `--preflight-only` to
validate locally without starting a distribution build or contacting a server.
The command refuses missing or unsafe configuration and prints field names,
never credentials. It does not establish signing-account authorization.

Supply `API_BASE_URL` (explicit HTTPS API URL), `PUBLIC_TRACE_ORIGIN` (explicit
HTTPS origin) and `TRACE_LINK_HOST` (the same host as that origin) through the
environment. `USE_MOCKS` and `PAYMENT_SIMULATOR_ENABLED` must be unset or exactly
`false`. The script passes these settings to Flutter. Release startup also
validates them before Firebase/network bootstrap, so bypassing the script cannot
silently use the emulator default or mock/payment simulator. Debug defaults are
unchanged. Direct release builds must supply these same Dart defines.

For Android, this environment-only command also requires `MAPS_API_KEY`,
`ANDROID_KEYSTORE_PATH` (absolute path to the real keystore),
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD`.
Supply secrets via the local/CI environment, never source control or command
arguments. Remove conflicting `android/key.properties` from this command's path
(use it directly with Gradle instead); an overriding local native trace host
must match. Native Gradle still validates the actual keystore and signing.

For iOS, configure `MAPS_API_KEY` in ignored `ios/Flutter/Secrets.xcconfig` and
ensure the effective `TRACE_LINK_HOST` in Release/Secrets.xcconfig matches the
requested host. Existing genuine signing team/provisioning must be configured
with Xcode; no identity is generated by the script. Distribution signing,
registered OAuth fingerprints, APNs, association files and physical-device
acceptance remain release gates.
